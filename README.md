# pi-goal-highlight

Renders the objective generated by `@narumitw/pi-goal` as a **[GOAL]** block with turquoise text on a dark blue background. The generated introduction, XML wrapper and code fence are not shown. Requires **Pi 1.0.0+**.

This companion extension uses Pi's public `registerMarkdownTransformer` API. The transformation runs only during transcript rendering. Original prompts, XML tags, model context, session entries, goal IDs, continuation markers and goal lifecycle remain intact. It also applies to old goal messages when Pi renders a resumed session.

## Install

```sh
pi install https://github.com/rodrigojager/pi-goal-highlight
```

Keep the original `pi-goal` installed. When an existing Pi session is idle, use `/reload`, then `/goal-highlight-preview` to inspect the colors without a goal or model request.

For a local checkout, use `pi -e ./index.ts`. Alternatively, load a wrapper from `~/.pi/agent/extensions` that imports this extension. Do not install both the package and the wrapper: choose one loading method.

## Behavior

- Recognizes goal start, resume, edited objective, waiting resume and automatic continuation messages.
- Colors only complete objective blocks in user messages with known pi-goal prefixes.
- Starts the highlighted area with `[GOAL]`, followed by the objective; there is no closing label.
- Wraps long text at terminal width, decodes one layer of pi-goal XML escaping and lets Pi render the objective's Markdown. Original prompts and stored messages remain unchanged.
- Leaves ordinary user messages, assistant messages and incomplete blocks untouched.
- Uses fixed RGB colors: background `#20303b`, foreground `#6ee7dc`.
- Requires no runtime dependency installation, timers, processes, prompt hooks or goal state access.

The colors apply to the objective's text area; Pi draws the surrounding message margins with its selected theme. No code fence is added by the extension. HTML export and RPC clients do not use the interactive Markdown transformer.

## Validation

```sh
npm test
```

The integration check additionally renders through the installed Pi `UserMessageComponent`. Set `PI_TEST_PACKAGE` to the absolute installed `@earendil-works/pi-coding-agent` directory to run it.
